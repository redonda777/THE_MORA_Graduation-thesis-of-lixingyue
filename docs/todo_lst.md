| 序号 | 步骤 | 工具 / 库 | 说明 |
|------|------|-----------|------|
| 1.1 | 安装图计算库 | `NetworkX` | 用于图的存储、构建与基础算法（含社区发现） |

## 第二阶段：文本预处理（Text Preprocessing）

| 序号 | 步骤 | 工具 / 方法 | 说明 |
|------|------|-------------|------|
| 2.1 | 语料观察与规则制定 | 人工观察 + 脚本统计 | 观察 OCR 标记、残字、特殊符号的分布规律 |
| 2.2 | 删除标点符号 | 正则表达式 / Python 字符串处理 | 古文原本无标点，句读为后人所加，需全部去除 |
| 2.3 | 清理 OCR 识别噪声 | 正则 / 规则替换 | 统一或删除 OCR 过程中产生的标记符号 |
| 2.4 | 残字处理 | 占位符（如 `□` 或特殊 token） | 古籍中看不清的字不能删除，需用占位符保留位置信息 |
| 2.5 | 文本规范化输出 | Python 脚本 | 确保所有版本句子对齐，准备进入编辑距离计算 |

## 第三阶段：句子间相似性 / 差异边计算（Weighted Edge Construction）

| 序号 | 步骤 | 工具 / 算法 | 说明 |
|------|------|-------------|------|
| 3.1 | 基础编辑距离计算 | 动态规划（Levenshtein Distance） | 记录 `insert`、`delete`、`replace` 三种操作及其位置 |
| 3.2 | 差异点提取与记录 | 自定义脚本 | 在 DP 过程中记录每一个 `replace` 操作的「替换前字符」与「替换后字符」 |
| 3.3 | **通假字关系分类** | 大模型（LLM）+ Prompt Engineering | 将差异字对输入大模型，判断其关系类别（同音 / 同义 / 同形 / 通假等），**共 5 类，需与中文系老师确认具体分类** |
| 3.4 | 定义差异化替换代价 | 规则配置表 | 不同关系类别赋予不同的 `replace` 代价（0 ~ 1 之间），例如：同形误抄代价低，同音通假代价略高 |
| 3.5 | 重新计算加权编辑距离 | 自定义动态规划 | 将标准编辑距离中的 `replace` 代价从 1 替换为模型判断后的权重值 |
| 3.6 | 设置相似性阈值 | 阈值过滤 | 差异过大的句子对（如三字中两字被替换）直接判定为无关，权重置 0，不连边 |
| 3.7 | 构建句子间加权边 | `NetworkX` | 将加权相似度作为边权重，连接不同版本的句子节点 |

> **关键算法概念**：
> - **标准编辑距离**：`delete`（删除）、`insert`（插入）、`replace`（替换），默认每种操作代价为 1。
> - **加权编辑距离**：根据字符关系类型动态调整 `replace` 代价，体现古籍文本的特殊亲缘关系。

## 第四阶段：图节点向量学习（Graph Representation Learning）

| 序号 | 步骤 | 工具 / 算法 | 说明 |
|------|------|-------------|------|
| 4.1 | 环境准备 | `PyTorch` / `PyTorch Geometric` 或 `DGL` | 安装图神经网络框架 |
| 4.2 | 图数据格式转换 | 框架自带 DataLoader | 将 `NetworkX` 图转换为 GNN 框架输入格式 |
| 4.3 | **无监督节点向量学习** | **VGAE（Variational Graph Auto-Encoder，变分图自编码器）** | 无需标签数据，学习所有节点（含虚拟节点）的低维向量表示 |
| 4.4 | 提取虚拟节点向量 | Python 脚本 | 重点关注「章节节点」和「书籍节点」的向量，用于后续亲缘关系分析 |
| 4.5 | 向量质量验证 | 可视化（t-SNE / UMAP） | 观察同类节点是否聚类，验证向量有效性 |

> **VGAE 作用**：通过重构邻接矩阵，在无监督条件下捕捉图结构特征，使语义/亲缘关系近的节点在向量空间中距离更近。

## 第五阶段：社区发现与亲缘分析（Community Detection）

| 序号 | 步骤 | 工具 / 算法 | 说明 |
|------|------|-------------|------|
| 5.1 | 选择社区发现算法 | **Girvan-Newman** | `NetworkX` 已内置，用于检测图中社区结构 |
| 5.2 | 适配带权图 | 修改/封装 `NetworkX` 算法 | 传统 Girvan-Newman 基于边介数（Betweenness）删除边，需适配带权场景（将权重 / 代价融入边强度计算） |
| 5.3 | 运行社区发现 | `NetworkX` (`community.girvan_newman`) | 对图进行迭代划分，得到社区结构 |
| 5.4 | 章节级亲缘关系映射 | Python 分析脚本 | 分析同一社区内的章节节点，推断不同版本间章节的参考关系 |
| 5.5 | 书籍级亲缘关系汇总 | Python 分析脚本 | 聚合章节级结果，推断版本间的整体亲缘关系 |
| 5.6 | 结果存储 | JSON / CSV | 保存社区划分结果与亲缘关系矩阵 |

## 第六阶段：交互式可视化展示（Visualization System）

| 序号 | 步骤 | 工具 / 技术栈 | 说明 |
|------|------|---------------|------|
| 6.1 | 前端框架选型 | `D3.js` / `ECharts` / `Cytoscape.js` / `G6` | 选择适合的 Web 图可视化库，推荐支持力导向布局与交互的库 |
| 6.2 | 后端接口开发 | `Flask` / `FastAPI`（Python） | 提供图数据、社区结果、句子文本的查询接口 |
| 6.3 | 图可视化基础展示 | 前端可视化库 | 展示所有节点与边，支持缩放、拖拽 |
| 6.4 | 交互功能：悬停聚焦 | 前端事件监听 | 鼠标悬停某节点时，高亮该节点及其关联边，其余淡化 |
| 6.5 | 交互功能：章节查询 | 前端搜索 + 后端接口 | 输入章节号（如"第五章"），定位并展示该章节在所有版本中的句子及社区关系 |
| 6.6 | 交互功能：社区高亮 | 前端样式渲染 | 以不同颜色区分不同社区，直观展示亲缘聚类结果 |
| 6.7 | 部署与测试 | 本地 / 轻量服务器 | 确保系统可运行，供人文学者使用 |

> **可视化目标**：为人文研究学者提供直观、可交互的亲缘关系探索界面。

## 核心算法与工具汇总

| 类别 | 名称 | 用途 |
|------|------|------|
| 图构建与存储 | **NetworkX** | 图的构建、层级边连接、社区发现 |
| 文本相似性 | **动态规划编辑距离（Levenshtein）** | 基础字符串差异计算 |
| 语义关系判断 | **大语言模型（LLM）** | 判断差异字对的通假/同音/同义/同形关系 |
| 图表示学习 | **VGAE（变分图自编码器）** | 无监督学习节点低维向量 |
| 社区发现 | **Girvan-Newman** | 基于边介数的社区划分 |
| 可视化 | **D3.js / ECharts / G6 / Cytoscape.js** | 交互式图可视化 |
| 后端服务 | **Flask / FastAPI** | 数据接口服务 |
